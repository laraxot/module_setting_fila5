# Setting module test coverage

## Overview

`Modules/Setting` is a minimal nwidart scaffold module (13 PHP files total: 1
controller, 3 providers, 1 config file, 1 empty seeder, 2 blade layouts + 1 view,
2 empty route files, 2 test bootstrap files). No custom business logic exists yet
— everything under `app/` is boilerplate generated by the module scaffolder and is
functionally inert (routes/web.php and routes/api.php are both empty, so
`SettingController` is not reachable from any HTTP route).

### PHPInsights

`vendor/bin/phpinsights` does not exist in this repo's vendor tree — confirmed
verified fact per repo memory `pest5-incompatibile-con-phpinsights`: Pest 5
requires `phpunit ^13.3` → `sebastian/diff ^9.0`, while `nunomaduro/phpinsights`
(max release 2.14.2, no v3) requires `sebastian/diff ^6|^7`. The two cannot
coexist in one lock file; this project chose Pest 5 and removed phpinsights
project-wide. This is a pre-existing, project-wide, already-documented gap —
not something to fix inside a single module's quality-gate pass.

### Coverage — not raised, documented as-is

Per task instructions: coverage may only be raised off a *real* fix (dead code
removed, or a test added for a concrete gap surfaced by phpmd/phpinsights).
Neither tool surfaced anything in this module — phpmd is clean, phpinsights is
unavailable project-wide. Inventing tests purely to move a percentage would be
the "fake test" anti-pattern the task explicitly forbids, so none were added.

**Baseline, measured, not estimated**: 0 test files, 0 tests, 0% line coverage.
Structural note for whoever picks this module up next: `SettingController`'s
`create()`/`show()`/`edit()` actions reference views `setting::create`,
`setting::show`, `setting::edit` that do not exist in
`resources/views/` (only `index.blade.php` is present), and neither
`routes/web.php` nor `routes/api.php` register any route to this controller at
all — so the controller is currently dead/unreachable code. This is a
functional/product gap, not a phpmd or phpinsights finding (no tool in this
gate flags "missing view" or "unrouted controller"), so it was left untouched
per the "no speculative fixes outside the tool's findings" scope of this task —
flagging it here for a future story instead.
